# CLAUDE.md

Сервис распознавания рукописного текста: Qwen2.5-VL через llama.cpp, HTTP API
на Flask и веб-интерфейс. Всё работает локально: документы не покидают машину.

## Как устроена работа

Задачи веду я. Агенты в `.claude/agents/` — исполнители с узкой ролью:

| Агент | Роль | Права |
|---|---|---|
| `planner` | Разбивает задачу на шаги, находит затронутые модули | Только читает |
| `implementer` | Делает один шаг плана | Правит код |
| `test-writer` | Пишет модульные тесты | Правит только `tests/` |
| `test-runner` | Прогоняет тесты и разбирает падения | Запускает и читает |
| `reviewer` | Ревью диффа перед коммитом | Только читает |
| `docs-writer` | Документация в `docs/` и README | Правит только `*.md` |

Полный цикл задачи — `/feature <описание>`, отдельные шаги — `/test`,
`/review` и `/docs`. Подробнее — [docs/AI_WORKFLOW.md](docs/AI_WORKFLOW.md).

Правила:

- Агенты не коммитят и не пушат. Коммит делаю я после ревью.
- Один шаг плана — один коммит.
- Реальные документы, сканы и журналы агентам не показываются: путь закрыт в
  `.claude/settings.json`. Для проверок — синтетические картинки из
  `tests/unit/support.py`.
- После каждой правки `.py` хук прогоняет `ruff check` по файлу: агент видит
  замечания сразу, а не на CI.

## Структура

```
src/app.py            Flask: API, Swagger, веб-интерфейс
src/ocr.py            пайплайн: предобработка, промпты, зоны, голосование
src/llamaserver.py    обёртка llama-server
src/logprobs.py       вероятности токенов по значениям JSON
src/schema.py         схемы документов из config/schemas
src/normalize.py      нормализация текста, чисел, дат, телефонов
src/dictmatch.py      сверка со словарями из data/dictionaries
src/confidence.py     оценка полей и очередь ручной проверки
src/storage.py        история распознаваний в SQLite
src/logging_setup.py  JSON-журналы, аудит, request_id
tools/watch_folder.py папочная обвязка: data/in -> data/out
tests/unit/           модульные тесты, общая подготовка в support.py
scripts/              запуск, остановка, журналы, скачивание модели
docs/                 API, схемы, настройки, архитектура
```

## Команды

```bash
python src/app.py                                           # сервис на :5002
python -m unittest discover -s tests/unit -v                # все тесты
python -m unittest discover -s tests/unit -p 'test_schema.py'  # один модуль
ruff check .                                                # линтер, как на CI
shellcheck scripts/*.sh                                     # скрипты
docker compose up -d --build                                # сервис в Docker
```

## Соглашения

- Python 3.11, строка до 100 символов, ruff с правилами E, F, W, B
  (`pyproject.toml`).
- Комментарии, документация и сообщения коммитов — на русском. Коммиты в
  стиле Conventional Commits: `feat(ocr): ...`, `fix(storage): ...`,
  `test(api): ...`, `docs(api): ...`, `ci: ...`.
- Ветки: `feature/<область>`, `test/<область>`, `docs/...`, `ci/...`; в
  `main` — слиянием без fast-forward.
- Сервис не выдумывает: пустое поле остаётся пустым, сомнительное уходит в
  `needs_review`. То же требование к коду постобработки: не «чинить» значение
  молча.
- Новый модуль пишет в журнал через `logging_setup`, со сквозным `request_id`.
- В тестах модель и llama.cpp всегда подменены заглушками: видеокарта и файл
  модели не нужны. CI гоняет те же тесты без GPU.
- Документация описывает то, что есть в коде. Примеры ответов API берутся из
  реального прогона, а не пишутся по памяти.
