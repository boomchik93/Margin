# Распознавание рукописного текста

HTTP-сервис, который читает рукописный текст со сканов, фотографий и PDF.
Работает на vision-language модели Qwen2.5-VL-7B через llama.cpp, локально,
на своей видеокарте: документы никуда не отправляются.

Два режима:

- **Свободный текст.** Сервис расшифровывает всё написанное от руки, строка
  за строкой. Печатный текст по умолчанию пропускается.
- **Поля по схеме.** Вы описываете документ в JSON — какие поля на нём есть и
  какого они типа, — и получаете значение каждого поля, оценку уверенности и
  список полей, которые стоит проверить глазами.

```bash
curl -F "file=@letter.jpg" http://localhost:5002/api/ocr
```

```json
{
  "success": true,
  "type": "image",
  "mode": "text",
  "text": "Привет!\nПишу тебе из Казани.",
  "lines": ["Привет!", "Пишу тебе из Казани."],
  "unclear_count": 0,
  "request_id": "a3f2c1d0",
  "duration_seconds": 6.4
}
```

## Что умеет

- **Отличает рукописное от печатного.** На анкете или бланке подписи полей
  напечатаны, а ответы вписаны от руки; в результат попадают только ответы.
- **Понимает расположение.** Одно и то же число значит разное в разных
  местах документа. Классический OCR вернул бы плоский текст, модель знает,
  к какому полю относится запись.
- **Не выдумывает.** Пустое поле возвращается пустым, неразборчивое слово в
  свободном тексте помечается знаком `[?]`, невозможная дата остаётся как
  прочитана и уходит на ручную проверку.
- **Сверяет со словарями.** Если у поля есть список допустимых значений,
  расхождение в одну-две похожие буквы исправляется, а значение, которого в
  списке нет, уходит на проверку с ближайшими кандидатами.
- **Оценивает уверенность.** По каждому полю — оценка 0..100 и причина; поля
  с нарушенным форматом попадают в `needs_review`.
- **Перечитывает трудные места.** Зону документа можно отдать модели
  отдельным крупным фрагментом, а номер или код — прочитать три раза и
  свести посимвольным голосованием.
- **Помнит, что вернул.** История распознаваний в SQLite, структурированный
  журнал и сквозной идентификатор запроса.
- **Работает с папкой.** Положили файл в `data/in` — забрали JSON из
  `data/out`.

## Требования

**Минимум:** Linux, NVIDIA GPU с 8 ГБ VRAM, 16 ГБ RAM, 20 ГБ на диске,
Docker 20.10+, Docker Compose 2.0+, NVIDIA Container Toolkit.

**Рекомендуется:** GPU с 11+ ГБ VRAM — тогда модель целиком помещается в
видеопамять.

Без видеокарты сервис работает, но страница обрабатывается минутами вместо
секунд: годится для проверки развёртывания, не для потока.

## Установка

```bash
# 1. Настроить окружение
cp .env.example .env

# 2. Скачать модель и проектор в models/ (~6 ГБ)
pip install huggingface-hub
scripts/download_model.sh

# 3. Собрать и запустить
docker compose up -d --build

# 4. Проверить готовность
curl -s http://localhost:5002/api/status
```

`"ready": true` — сервис готов принимать файлы. Если `false`, смотрите
`model_exists` и `llama_exists` в том же ответе.

Веб-интерфейс: http://localhost:5002

Первая сборка образа долгая: внутри компилируется llama.cpp с CUDA.

### Без Docker

Нужны Python 3.11 и собранный llama.cpp (`llama-mtmd-cli`, по желанию
`llama-server`) в `llama.cpp/build/bin/` либо путь к нему в
`LLAMA_CLI_PATH`.

```bash
pip install -r requirements.txt
scripts/download_model.sh
python src/app.py
```

## Использование

### Свободный текст

```bash
curl -F "file=@note.jpg" http://localhost:5002/api/ocr

# читать и печатный текст тоже
curl -F "file=@page.png" -F "printed=1" http://localhost:5002/api/ocr

# рукопись на английском
curl -F "file=@note.jpg" -F "language=en" http://localhost:5002/api/ocr
```

### Поля по схеме

В комплекте есть пример — `config/schemas/example_form.json`, анкета с ФИО,
датой, телефоном, городом и отметкой о согласии.

```bash
curl -F "file=@form.pdf" -F "schema=example_form" http://localhost:5002/api/ocr
```

```json
{
  "success": true,
  "type": "image",
  "mode": "form",
  "schema": "example_form",
  "fields": {
    "full_name": "ПЕТРОВА АННА СЕРГЕЕВНА",
    "birth_date": "14.03.1991",
    "phone": "89001234567",
    "city": "Казань",
    "participants": "3",
    "comment": "",
    "consent": "checked",
    "signed": "checked",
    "date": "02.09.2026"
  },
  "confidence": {"full_name": 55, "birth_date": 70, "phone": 70, "city": 55,
                 "participants": 70, "comment": 0, "consent": 70,
                 "signed": 70, "date": 70},
  "dict_status": {"city": "exact"},
  "needs_review": [],
  "request_id": "5b1e77aa"
}
```

Свою схему положите рядом: `config/schemas/my_doc.json` станет доступна как
`schema=my_doc` без перезапуска. Формат — [docs/SCHEMAS.md](docs/SCHEMAS.md).
Схему можно передать и прямо в запросе, полем `schema_json`.

### Папочная обвязка

```
data/in/scan.pdf  ->  data/out/scan.json  +  data/in/archive/scan.pdf
```

```bash
# демон в Docker (отдельно от ocr-service)
docker compose --profile watcher up -d ocr-watcher
docker compose --profile watcher rm -sf ocr-watcher      # остановить

# то же без Docker
python tools/watch_folder.py --in data/in --out data/out
python tools/watch_folder.py --in data/in --out data/out --schema example_form --once
```

Файл берётся только дописанным, результат появляется в `out/` целиком,
оригинал уезжает в архив даже после сбоя. Обвязка держит свой `llama-server`
и поэтому не поднимается вместе с `ocr-service`: на одной карте они делили бы
видеопамять.

## Что где лежит

```
src/                сервис и пайплайн
config/             настройки, схемы полей (config/schemas)
data/dictionaries/  словари допустимых значений
data/in, data/out   папочная обвязка
data/results.db     история распознаваний (создаётся сама)
logs/               app.log, audit.jsonl, errors.log
models/             файлы модели, ~6 ГБ
tools/              папочная обвязка
tests/unit/         модульные тесты
```

На постоянном диске должны жить `data/`, `logs/`, `models/` и `config/`.

## Тесты

```bash
python -m unittest discover -s tests/unit
```

Модульные тесты не требуют ни модели, ни видеокарты: модель в них подменена
заглушкой. Проверяется всё вокруг неё — разбор ответа, схемы, нормализация,
сверка со словарями, голосование, HTTP-слой, история, папочная обвязка.

## Ограничения

- **Качество исходника решает больше, чем настройки.** Скан в 300 DPI
  читается заметно лучше скана в 100 DPI; на низком разрешении рукописные
  `4` и `9`, `1` и `7` неразличимы, и никакой промпт этого не исправит.
- **Страница должна лежать ровно.** Автоповорота нет: повёрнутый на 90° скан
  читается намного хуже.
- **Зоны схемы привязаны к вёрстке.** Они задаются в долях страницы и
  рассчитаны на одинаково отсканированные документы одного вида.
- **Модель ошибается.** Уверенность и `needs_review` сужают круг проверки,
  но не заменяют её там, где цена ошибки высока.
- **Скорость.** С зонами на страницу уходит несколько вызовов модели; при
  вызове через CLI модель ещё и загружается заново на каждый проход.
  Постоянная нагрузка — повод включить `LLAMA_BACKEND=server`.

## Безопасность и данные

Аутентификации нет: сервис рассчитан на работу внутри своей сети. При выносе
наружу ставьте перед ним reverse-proxy с авторизацией; заготовка —
`config/nginx.conf.example`.

Распознанный текст сохраняется в `data/results.db` и в `logs/audit.jsonl`.
Если вы обрабатываете документы с персональными данными, эти директории
требуют той же защиты, что и сами документы. Хранение отключается:
`RESULTS_DB_ENABLED=0` и `AUDIT_LOG_CONTENT=0`.
